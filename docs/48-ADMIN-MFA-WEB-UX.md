# V1 #30 Admin MFA Web enrollment UI (partial)

## Scope and security

The Paperbound administrator shell's **Settings** route mounts a real bilingual, responsive MFA enrollment panel implemented with React and the existing direct-TLS NestJS API. The panel does **not** expose private books, member records, catalogs, admin CRUD, recovery resets, initial superadmin bootstrap, dashboard metrics or fake successful actions. Existing catalog/member/admin navigation remains a truthful disabled placeholder.

The panel **fails closed** whenever its actual browser URL is not HTTPS. The Vite dev server at `http://127.0.0.1:4173` is therefore a safe layout preview, not a way to log in. No password, TOTP input, secret, or request to `/v1/` is shown/sent on HTTP. The server independently requires its own *actual direct TLS application socket* and explicit `FOLIO_WEB_AUTH_MODE=direct-tls-only` and `FOLIO_ADMIN_TOTP_HTTP_MODE=direct-tls-only`; it cannot be enabled via client headers. The UI has no feature-flag override, fallback local authentication, synthetic success or bypass for localhost.

## Same-origin browser workflow

- When the UI is mounted over HTTPS, it probes `GET /v1/auth/web/csrf` using **same-origin fetch**, browser-managed `credentials:'same-origin'`, `redirect:'error'`, `cache:'no-store'` and no-referrer. The returned 43-char HMAC-CSRF string is kept only in temporary component state. A 401 permits display of the signed-out form; 404/503 and other bootstrap failures display an unavailable state rather than pretending an administrator is connected.
- `POST /v1/auth/web/login` uses a bounded email and password form. Server-managed `__Host-folio_session` stays Secure/HttpOnly/SameSite=Strict; JavaScript never reads/stores it. The password is cleared from React state at submission and is not logged, copied to URLs or persisted. After 204 the client bootstraps the CSRF header; login never invents an admin role.
- `POST /v1/admin/mfa/totp/enroll` accepts an empty object and a valid CSRF header. A strict parser accepts only a server-returned 160-bit base32 seed and ISO expiry. The displayed secret is **in memory only** and can be dismissed immediately; there is no local/session storage, clipboard auto-copy, analytics or QR provider. No external host gets the secret.
- `POST .../confirm` accepts exactly six ASCII digits. A 204 **confirms the enrolled authenticator but does not grant administrator permission**; the UI immediately clears both the seed and the code and requires a different unused TOTP to continue.
- `POST .../verify` accepts another fresh six-digit code. It only displays `verified:true` and the server-generated device MFA expiry after strict runtime JSON checks. No admin catalog/member action becomes active without a separate backend RBAC-protected API. `POST /v1/auth/web/logout` uses the existing CSRF header; successful 204 drops all in-memory view state and trusts server cookie revocation.
- Invalid code, revoked session, role denial, cross-origin/CSRF rejection, unavailable backend and offline mode have localized, non-enumerating status/error text. Sensitive requests are never queued or retried automatically. If the panel is navigated away from, React unmounting discards the secret; refreshing requires a fresh live server session bootstrap.

## Evidence and remaining blocked work

`apps/admin/src/admin-mfa-client.spec.ts` validates HTTPS-only access, six ASCII digits, exact base32/expiry response shape and hidden-token/extra-field negatives. `apps/admin/src/AdminMfaPanel.spec.tsx` proves SSR/HTTP cannot render a password/code/secret form. `e2e/admin-mfa-safe.spec.ts` checks Chrome over actual local HTTP makes **zero** `/v1/` authentication calls, no sensitive inputs, TR/EN language switch, 390px responsive layout and keyboard navigation. Existing `admin-totp-https-smoke` provides **real ephemeral HTTPS NestJS plus PostgreSQL** transport tests for cookie+CSRF, secret enrollment, confirm, replay and per-device proof. Combined they establish a UI transport implementation, **not** an end-to-end browser HTTPS + real user authentication test or a native mobile test.

**Not complete / human-controlled:** authorized first-superadmin provisioning, production cert/origin/CSP/cookie infrastructure review, full HTTPS browser-to-backend live automated E2E, secure recovery/reset and outside identity attestation, WebAuthn, real native secure device storage + device QA, password reset/verification delivery, administrator CRUD/RBAC API and approved production rollout. Release security dependency gate #7 remains blocked. No production build or environment/secret was deployed by this PR.
