# Two-operator canonical work identity evidence review (#12, partial)

## Scope: recorded judgment, never merge or publish

Migration `0019_canonical_work_match_review.sql` creates `canonical_work_match_reviews`, a forward-only **existing draft work vs existing draft work** comparison ledger. Each pair is stored once, sorted by stable work UUIDs, enforced by a database CHECK + UNIQUE index. Work rows use FK RESTRICT; source content, authors, editions, personal books and rights tables are untouched. A distinct or deferred verdict **NEVER** changes canonical UUIDs, work/author links, title variants, import conflict outcome, content revisions, active rights, or publication. It is not a publication approval or a source-license verification.

The backend derives a safe `shared_source_sha256` (byte-identical immutable source revision), `same_title` (exact original title and language), or `manual` evidence label, in that order. No raw text, hashes, account identity, evidence file or user-search result is returned over HTTP. Internal `evidenceDigest` SHA-256 includes BOTH current canonical title/language/status/metadata versions and bounded unique raw digest sets. Max 1000 evidence rows for the two selected works; exceeded limits fail closed, not partially compared. An exact SHA match is **not** proof that rights, translation, edition, country or canonical identity match.

## Protected default-off API

The existing `FOLIO_ADMIN_CATALOG_HTTP_MODE=direct-tls-only` and separate `FOLIO_ADMIN_CATALOG_WRITE_MODE=direct-tls-only` flags remain required (write only for POST/PATCH). Every endpoint requires application socket HTTPS, authenticated nonrevoked account and session, same-device current MFA, live PostgreSQL membership and `catalog:read` or `catalog:edit` permission. Browser calls use Secure HttpOnly same-origin cookie + exact Origin and HMAC-CSRF for POST/PATCH, not client Bearer or role claims. No dangerous reverse-proxy `X-Forwarded-Proto` trust.

- `GET /v1/admin/catalog/works/:workId/match-reviews?cursor=UUID` lists up to 20 reviews sorted by review UUID, with opaque peer UUID/title, evidence class, status, revision, current-snapshot flag, and next cursor; no private content, source digest, reviewer identity or reason. No user search.
- `POST /v1/admin/catalog/works/:workId/match-reviews` accepts ONLY `{candidateWorkId}` for two *already existing DRAFT* canonical works. Reversed pair and identical evidence re-proposal return the same row with `changed=false`, without extra audit. If either work changes, re-proposal explicitly resets the old ticket to pending, advances review revision, invalidates the old decision, and emits a correlated audit.
- `PATCH /v1/admin/catalog/works/:workId/match-reviews/:reviewId` accepts strict `{expectedVersion,decision:'distinct'|'deferred',rationale}`, rationale 24..1200 characters. **A second, different** currently MFA-verified `catalog:edit` editor must decide. The proposer cannot self-review even from another device or with forged `x-user-id` header. The canonical work revision and evidence digest must still match. Concurrent reviewers serialize on the same review row: exactly one decision, the other receives 409. All evidence/version, changed status, trusted actor trace and before/after audit live in the same PostgreSQL transaction. Neither API admits `merge`, `allowImport`, `publish` or `rightsApproved`.

An invalid/revoked session or role gets 401/403, unknown work/review 404 after authorization, invalid/malicious body 400, same-authority reviewer 403, stale/evidence collision 409, and unavailable backend 503. No optimistic auto-submit and no opaque error internals.

## Real editor UI and tests

`AdminWorkMatchReviews.tsx` is visible only by a deliberate button on a verified **DRAFT** work detail under existing Paperbound admin. The user supplies the known canonical work UUID, not a person ID. It queries the authenticated review list; proposal/decision require explicit separate actions, explanatory rationale, and fresh CSRF for each write. 200/201 body is strictly validated, then a second independently verified GET refreshes records. Network ambiguity/409 locks further writes until the operator explicitly reloads. TR/EN and 390px mobile design use standard admin tokens/labels, while original catalog text/rights are never modified. UI Playwright uses an explicitly mocked HTTPS API; server smoke separately covers **real** Folio-only PostgreSQL + temporary HTTPS + MFA/CSRF permissions, audit integrity, race and stale digest evidence.

`pnpm check`, `admin-catalog-https-smoke`, `pnpm e2e`, Expo Web/Android/iOS JS exports, CodeQL, license and nondeploy Docker are GitHub Actions verification gates. Real Android/iOS device tests and live browser + actual PostgreSQL in the same E2E process remain separate incomplete acceptance.
