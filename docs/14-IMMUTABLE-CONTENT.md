# Immutable source and semantic content revisions (#13)

## Implemented foundation
Forward-only Drizzle migration `0002_lively_dazzler.sql` creates provenance, content revisions, chapters, and semantic blocks. Revision identifiers, stable chapter/block identifiers, chapter and block ordinals, verbatim source text, source locator, SHA-256 and independent normal/RSVP/audio flags are stored. The source asset key/hash is metadata only until the dedicated storage adapter verifies and preserves the raw bytes under #26. No OCR, text restoration, AI correction or synthesis occurs.

A strict `@folio/contracts` input validator rejects missing source text, duplicate IDs, gaps in reading order, foreign parent blocks, and footnotes/endnotes, page numbers, running headers, publisher notes or image refs enabled for RSVP/audio. `@folio/db` verifies the SHA-256 for each exact UTF-8 block, creates a separate draft revision and audit row in a transaction, and never updates source content in place. New revisions may reference their parent only when its edition matches; translations and sound files will link the exact revision in later V1 issues.

Postgres protection triggers reject changes and deletion of provenance, chapter and block records, and reject changes/deletion of content revision source identity. Revision status may be updated by future audited approval workflows, not in this foundation. Existing user reading cursor migration, diff editor, integrity review, rights and publishing checks remain incomplete and are **not** treated as delivered.

## Internal read-only semantic revision difference foundation (#13 partial)

`@folio/db` now exports `getInternalRevisionMetadataDiff(db,{editionId,fromRevisionId,toRevisionId,cursor?,limit?})` plus a pure `compareSemanticRevisionMetadata` helper. **These are internal only**: no anonymous, user, public-library or administrator HTTP route is enabled by this change. Callers that expose a future UI must independently verify current persisted same-device MFA/RBAC, edition/work scope, source rights, current country permissions and user private-library isolation before returning any result.

The reader compares two immutable revisions **from the SAME edition** inside one `SET TRANSACTION READ ONLY` + `REPEATABLE READ` PostgreSQL snapshot. SQL projections explicitly exclude `sourceText`, the raw artifact key, provenance evidence and source bytes. Chapters compare only stable chapter UUID/order and whether the heading changed, never echo heading text. Blocks compare **stable block UUID** and SHA-256, chapter UUID, ordinal, kind, parent, locator fingerprint and normal/RSVP/audio include flags. The diff returns change classes `added/removed/text_changed/metadata_changed/moved`, per-class counts and at most 100 deterministic UUID-cursor rows per page with nullable next cursor. Text/locale similarity **never implies block equivalence**; a removed UUID plus new UUID remains a removal/addition even if the SHA is identical. No AI generation, OCR recovery, automatic rewriting, translation alignment, source correction or hidden source mutation is invoked.

A defensive cap (100,000 blocks and 10,000 chapters per revision) fails closed instead of returning incomplete evidence. Diff functions do not audit or write by themselves, because they are pure internal reads; protected future admin UI must handle access audit separately. `packages/db/src/content-diff.spec.ts` covers changed hashes, moved blocks, changed flags/locators, deterministic source-independent output, renamed chapters, duplicate ID denial and *no guessed text alignment*. Real isolated `folio_test` `content-smoke` adds two immutable follow-on revisions, tests a hash modification, removed footnote, added paragraph and moved stable block, 1-item stable pagination, cross-edition null, and no copyrighted/source text in the diff. Existing original revision remains immutable, and the existing PostgreSQL immutability triggers and audit remain in effect.

**Still required** to close #13: private-file SHA validation, publisher/rights-approved source workflow, authentic admin MFA-gated diff endpoint and responsive 7-tab editor, semantic chapter/block approval, corpus-scale diff performance validation and native/web reader anchor migrations. This does not count #13 completed or unlock release.

## Verified canonical revision SHA diff over real HTTPS (#13 partial)

`GET /v1/admin/catalog/works/{workId}/editions/{editionId}/revisions/{toRevisionId}/diff?fromRevisionId={uuid}&limit=1..100&cursor={uuid?}` is default **OFF** and can be read only when `FOLIO_ADMIN_CATALOG_HTTP_MODE=direct-tls-only`, the Nest application's actual socket is encrypted, and the caller has a current verified account + active session + same-device MFA proof + persisted `catalog:read` permission. Web requires the exact same-origin Secure HttpOnly session cookie; native bearer transport is separate. Browser Origin/host-mixed bearer transport and forged request claims are rejected. This endpoint never grants source publication, country rights or public catalog access. No Web/client diff UI is silently activated.

`getVerifiedAdminRevisionMetadataDiff` reuses the same **REPEATABLE READ PostgreSQL transaction** as verified account/session/MFA/role `FOR SHARE` locks, canonical `editionId→workId` ownership and both `content_revisions` metadata and chapter/block SELECTs. As auth needs locking, the verified callback cannot mark the transaction `READ ONLY`; it nevertheless executes no writes. Internal non-HTTP `getInternalRevisionMetadataDiff` still uses `SET TRANSACTION READ ONLY`. A wrong work, edition or revision UUID returns 404 only after authorization, malformed/forged pagination returns 400, expired factor or revoked role 403. HTTP is disabled by default and even `x-forwarded-proto` does not open it.

The response is a strict `@folio/contracts` Zod allowlist: edition/revision/block/chapter UUIDs, change kinds and summary counts, SHA-256, chapter ordinal, kind and normal/RSVP/audio include flags, bounded deterministic cursor. It returns **NO** source text, raw artifact locator, provenance evidence, reader/private books, identities or rights decisions. `apps/server/src/scripts/admin-catalog-https-smoke.ts` uses synthetic `folio_test` immutable revisions and real temporary application TLS to verify current Web/MFA native/editor/read-only permissions, malformed/foreign scope denial, cross-origin rejection, SHA-only 1-item pagination, no original/edited source body in JSON, expired MFA, feature-off denial and matching Swagger OpenAPI snapshot. No public publish/rights override or production deployment is introduced.

Remaining acceptance: responsive diff reviewer UI, real-source artifact hash/storage linkage and audit-scoped human review, full chapter/block editor with manual approval and immutable cursor migration. #13 and #22 remain open.
