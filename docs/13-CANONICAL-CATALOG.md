# Folio canonical author/work foundations (#12)

## Implemented draft schema
Forward-only Drizzle migration `0001_public_ben_urich.sql` adds author aliases, global source-scoped external author IDs, multilingual work titles, distinct edition IDs, edition contributors (including translators) and per-edition identifiers (including ISBN). The existing UUID work, author and work-author join remain intact, and title/ISBN are **not globally unique identifiers**. Edition and translation variants belong to one canonical work but are never collapsed to the same edition ID.

## Internal transactional commands
`@folio/db` exports `createCanonicalAuthor`, `createCanonicalWork`, and `getCanonicalWorkDetails`, validated against typed `@folio/contracts` inputs. Work creation requires at least one author and cannot publish a book: every new work and edition is explicitly `draft`. Related author/edition/title/identifier rows and the audit record are written in the same DB transaction. A broken contributor foreign key rolls back the entire operation. No unauthenticated public author/work CRUD endpoint has been exposed, and there is **no people-search API**.

Source rights, country access policy, manual publication approval, full content revision model and actual admin CRUD are subsequent issues (#13-#23). Duplicate match suggestions based on source hashes/human review are also separate import work. No automated external source, OCR or AI generation runs here.

## Real Ubuntu DB evidence
`pnpm check` PASS including lint, strict TS, unit/HTTP, build, design matrix and OpenAPI. `bash infra/lab.sh migrate` PASS on existing lab DB with forward-only migration. `bash infra/lab.sh test-db` PASS on separate Folio-only `folio_test` DB. `bash infra/lab.sh catalog-smoke` PASS: test fixtures include aliases/external source IDs, N:M work authors, two TR/EN editions with distinct contributors, same ISBN in distinct editions, two works with the same title but unique UUIDs, FK failure rollback and corresponding audit record. All fixture works remain draft; no catalog/public URL exposes them. `folio_test` stores synthetic records for repeatable diagnostics only; never real user data.

This is partial #12 until authenticated admin workflows, rights-aware read/search, responsive UI and all acceptance tests are finished.

## Deterministic internal read snapshots (#12 partial)

`getCanonicalWorkDetails(db, workId)` now validates the canonical UUID **before** querying, then returns the work, author links, multilingual titles, independently identified editions/ISBNs and edition contributors inside a **single PostgreSQL read-only REPEATABLE READ transaction**. The previous independent reads could observe mismatched states if a later editorial transaction committed between queries. The internal helper is **not a public catalog endpoint**: it deliberately does not claim country rights, publication or owner visibility. Never expose its drafts to a public or unauthenticated client; #14 and admin MFA/RBAC gates remain mandatory before mounting any protected API.

Every relation has an explicit stable order: work authors by `sort_order, author_id`; titles by `language, kind, title, title_id`; editions by `language, label, edition_id`; ISBN/identifiers by `kind, value`; edition contributors by `sort_order, role, author_id`. IDs, not array indices, identify selections and future progress/translation links. This is a deterministic presentation/order guarantee, **not** a claim that English or Turkish is the user's preferred language; clients still select a language/edition by ID.

The Folio-only `folio_test` PostgreSQL `catalog-smoke` now creates deliberately out-of-order authors, TR/EN titles, editions, contributors and identifiers, asserts stable sorted output and repeat-read equality, plus `null` for an unknown UUID and rejection of a malformed ID. The existing rights, content and prepared translation/audio synthetic smoke suites check their internal consumers. No migration, original text edits, dedup/auto-merge, AI/provider calls, public route, secret or deploy. This is **partial #12** until rights-aware/admin API, authenticated CRUD and responsive UI acceptance are completed.

## Authenticated canonical metadata search (partial #9/#12)

Internal canonical work and author search may now be reached only via the explicit, default-off, application-direct-TLS `GET /v1/admin/catalog/works` and `GET /v1/admin/catalog/authors` endpoints. Each request executes the metadata SELECT *inside* `withVerifiedAdminPermission(...,'catalog:read',...)`, preserving the DB locks on the active session, same-device MFA and active persisted role for the entire query. Work draft status, original title/language and canonical author/alias name are available to authorized administrators; user books, book bodies, source artifacts and public publishing are not. Query shape is strict `q,limit,cursor`, with literal wildcard handling and UUID cursor. Real isolated PostgreSQL + ephemeral HTTPS regression is `bash infra/lab.sh admin-catalog-https-smoke`. Actual admin role/bootstrap, publication approval, client UI and mobile QA remain under their original issues; #12 is not accepted as complete.

## Transaction-verified administrator draft writes (partial #9/#12)

Two default-disabled, strictly direct-TLS **POST** endpoints now create canonical authors and their alias/external-ID metadata or unpublished canonical works with author links, multilingual titles and 0+ editions/contributors. In addition to the existing `FOLIO_ADMIN_CATALOG_HTTP_MODE` for reading, writes require the independent `FOLIO_ADMIN_CATALOG_WRITE_MODE=direct-tls-only` flag. A persisted, current `catalog:edit` administrator role and **same-device MFA proof** are mandatory, and the exact DB authorization transaction also performs the inserts and correlated audit. No user-controlled actor or request ID, no public route to approve source/country/translation/audio rights, no publication state accepted or returned other than `draft`, and no source text mutation. Existing importer/CLI trusted-actor functions remain for internal use, sharing the same insertion primitives without their own authorization claim.

The isolated `admin-catalog-https-smoke` covers success and rollback, including a contributor FK error *after* work/edition insertion and author external-ID uniqueness collision, and verifies no partial rows or forged-audit owner. Browser cookie + HMAC-CSRF and independent native bearer paths are both tested over real TLS. Work remains incomplete until rights-aware public reads, full admin edit/detail workflow and actual responsive/browser-native QA pass original issues. The production release gate is unchanged.

## Permission-locked canonical detail snapshots (partial #12)

Authenticated administrators can now inspect a single work's ordered authors, TR/EN title variants and independently versionable edition identifiers/contributors using `GET /v1/admin/catalog/works/:workId`, and a single author's aliases/source-scoped external identifiers using `GET /v1/admin/catalog/authors/:authorId`. Both routes are default-off behind the existing `FOLIO_ADMIN_CATALOG_HTTP_MODE=direct-tls-only` actual socket TLS gate and require a live `catalog:read` DB permission + **same-device MFA**. Editor, read-only, rights or other genuinely granted roles can access only according to their current persisted permissions, never forged headers. The client-supplied UUID and query are strictly parsed; unknown IDs get a generic 404 only after successful permission validation.

`readCanonicalWorkSnapshot(tx,id)` now powers both the original internal `getCanonicalWorkDetails` read-only transaction and the verified admin detail query. The latter passes the `{isolationLevel:'repeatable read'}` option to the authorization wrapper, so account/session/MFA/membership locks and **all** related SELECTs share a single snapshot. It cannot `SET TRANSACTION READ ONLY` while taking those DB `FOR SHARE` authorization locks; nevertheless only explicitly projected canonical metadata is selected and returned. The internal implementation still sets `SET TRANSACTION READ ONLY`. The author detail query uses the same RBAC-locked isolation level for aliases and external ID rows, with stable sorting.

The `adminCatalogWorkDetailSchema` and `adminCatalogAuthorDetailSchema` are strict allowlists: no `createdAt`, raw source text, content revision body, private user book, personal identifiers or rights evidence. The canonical work remains **draft** until independently reviewed publication and territorial rights gates permit a separate public catalog action; this admin read never grants publication or audio/translation rights. Real Folio-only HTTPS/PostgreSQL regression creates synthetic work + author details, deliberately shuffled author and edition order, checks UUID-stable result equality, MFA/member/guest/role-revoke/expiry denials, normalized errors and feature shutoff. No provider calls, external book downloads, data migration or live deployment occurred. Remaining #12 admin CRUD, rights-aware/public endpoint and responsive QA are explicitly not complete.

## Version-conditional canonical metadata PATCH (partial #12)

Forward-only `0017_canonical_metadata_versions.sql` gives existing and newly drafted `authors` and `works` a `metadata_version INTEGER NOT NULL DEFAULT 0 CHECK >= 0`. A metadata version is a **scalar editable metadata version**, not a source-content revision, edition ID, translation alignment or publication approval. Old UUIDs and original book text are unchanged. This migration is forward-only (no destructive DROP/DELETE) and must run via the dedicated Folio migration runner before the updated API starts.

The explicit default-OFF direct-application-TLS `PATCH /v1/admin/catalog/authors/:authorId` and `PATCH /v1/admin/catalog/works/:workId` endpoints additionally need `FOLIO_ADMIN_CATALOG_WRITE_MODE=direct-tls-only` and fresh `catalog:edit` permission + same-session device MFA (separate from read-only roles). Every request supplies a strict `expectedVersion` and at least one permitted field. Both pass the server-owned request UUID (not a forged `x-request-id`) and actor from `withVerifiedAdminPermission`, preserving session/account/MFA/role locks while `SELECT ... FOR UPDATE` locks the target row. One of two writers of version `N` updates the row to `N+1`; the other receives safe `409 CONFLICT`, with **no unauthorized audit**. This avoids lost updates and permits clients to reload before retrying. Unrecognized UUID 404 only follows authorization; no client role/actor/owner selectors accepted.

Author edits permit canonical and sort name changes and optional **complete replacement** of alias and source-scoped external-ID lists; omitting lists preserves them while empty arrays clear the respective list. These changes, their old/new values, unique-source constraints and incremented revision, and a trusted `author.metadata.update` audit row commit or roll back **atomically** in one PostgreSQL transaction. A collided external ID rolls back all author/name/alias changes. Work edits permit only original canonical title and/or first-publication-year on works whose status remains `draft`, maintain the canonical `work_titles.kind='original'` relation for original language, and create one original title link for legacy metadata if absent. They never alter immutable source text, edition/revision content, publication rights, active approval or a published work. The `work.metadata.update` audit stores trusted request correlation and before/after title/year/status/version. An attempt to edit published work metadata with the draft editor receives 409. Version numbers are surfaced only in explicit admin detail/patch DTOs; no public catalog route is enabled.

The live synthetic `folio_test` TLS test verifies explicit flags, editor vs read-only MFA role, foreign actor/role/request headers, invalid publish/content/query inputs, normalized 400/401/403/404/409 errors, simultaneous version `N` editors exactly one 200 and one 409, committed multilingual/edition consistency, full alias/external-ID replacement, before/after audits, same-origin HMAC-CSRF Web PATCH vs forged/cross-site, expired-factor/revoked-role denial, OpenAPI schema and independent write-mode shutoff. These are **backend metadata edits only**: full edition/content/admin responsive CRUD UI, rights-aware publishing, native-device and public search acceptance remain separate, so #12 cannot yet close.

## Verified DRAFT work relation append (partial #12)

`POST /v1/admin/catalog/works/:workId/editions`, `.../titles` ve `.../authors` yeni *metadata* ilişkileri ekler. Her biri gerçek doğrudan TLS + iki ayrı katalog read/write opt-in + current-device MFA, PostgreSQL saklanan `catalog:edit` yetkisi, native bearer veya exact-origin Secure HttpOnly browser cookie+HMAC-CSRF gerektirir. Girdi `expectedVersion` mevcut GET detayındaki `work.metadataVersion`'dır. Mevcut work satırı `SELECT FOR UPDATE` ile kilitlenir; yalnız `draft` durumunda, beklenen sürüm eşleşirse nested edition/identifiers/contributors, translated/alternate title veya author role/order bağı oluşturur. Parent sürüm **N→N+1** ve güvenilir actor/requestId + önceki/yeni sürüm audit **aynı veritabanı transaction** içinde commit olur. Yarışan yazarlardan biri 201 diğeri 409 alır; rollback edilen ilişkide yarım baskı kaydı veya audit kalmaz.

- **Edition:** TR/EN dil, label, opsiyonel publisher, çoklu source-specific ISBN/diğer identifier, canonical author FK'li translator/illustrator/editor katkısı. Yalnız `status=draft` sunucuda sabittir. Aynı work içinde birden çok baskı ve birbiriyle çelişmeyen ISBN kaynağı olabilir; title/ISBN tekil kanonik eser anahtarı değildir.
- **Title:** yalnız `kind=alternate|translation`. Buradaki translation sadece **başlık metadata**sıdır; çeviri kaynak metni, kelime hizalaması, hak veya hazır yayınlanmış dil içeriği varsayılmaz. Orijinal başlık bu endpoint üzerinden değiştirilemez.
- **Work author:** ikinci/yeni doğrulanmış kanonik yazar için `authorId`, `contribution=author|co-author|editor`, `sortOrder`; mevcut author-work bağı PK ile çoğaltılamaz, tanımsız UUID FK reddedilir.
- **Denetim:** `edition.create`, `work.title.add`, `work.author.add` eylemleri source text ve özel kullanıcı kitaplarından ayrıdır. Her başarılı yanıt yalnız kayıt UUID(leri), parent work UUID, sürüm ve baskı taslak durumunu döndürür. Çoklu baskı/yazar ilişkilerini tek kanonik work anahtarı altında tutar.

Gerçek `folio_test` PostgreSQL üzerinde ephemeral doğrudan HTTPS smoke, 400/401/403/404/409/201, bad FK rollback, duplicate identifier, same-device MFA, Web CSRF/cross-site, read-only rol reddi, parent version conflicts (eşzamanlı iki editör), stable GET relational snapshot, OpenAPI and default-off flag testleri koşuludur. Bu **append-only kısmi admin backend**dir; edition update/delete, multiselect browser forms, dedup/reviewer onayı ve yayın-hak QA tamamlandı anlamına gelmez. #12 açık kalır.

## DRAFT edition metadata revision (partial #12)

`PATCH /v1/admin/catalog/works/{workId}/editions/{editionId}` only edits an already DRAFT edition of a DRAFT parent work after verified opt-in direct TLS + current PostgreSQL session/device MFA/role `catalog:edit` authorization, and exact-origin cookie HMAC-CSRF for Web. `expectedVersion` is the parent's canonical metadataVersion and uses the same parent `SELECT FOR UPDATE` serialization as author/work PATCH and relation POST. This edit never changes `edition.id`, `edition.work_id`, edition **language**, immutable source revisions, book body, publication status, rights approval, translations/audio or user reading progress. The editor can change `label`, nullable `publisher`, and optionally provide **complete replacement** `identifiers` (ISBN/other) and `contributors` (canonical author FK, role/order) arrays; omitted lists remain untouched, `[]` clears only that metadata list. Linked content revisions continue to reference the same stable edition UUID.

The edit locks the edition row and parent work in the same permission-verified PostgreSQL transaction, validates `status=draft`, calculates the complete old/new value sets, performs replacement DML + `works.metadataVersion=N+1` and inserts server-owned actor/request UUID audited `edition.metadata.update` **before/after** atomically. Concurrent edits at the same N give one 200 and one 409; late bad contributor FK rolls back *every* change and version/audit. Invalid rights/status/language/content/admin ID keys are strict 400; missing edition under a permitted parent is 404 only after current MFA. Server feature gate defaults off, no public route/prod rollout. The dedicated `folio_test` ephemeral HTTPS smoke checks CSRF, read-only denial, cross-site, stale and simultaneous revisions, publisher clear, preserved ISBN/translator association, and audit actor/trace. The full editor UI update and rights/publish/dedup acceptance remain open.

## Content-hash-backed possible canonical match suggestions (partial #12)

The internal, authenticated-by-CLI-only prepared import preview compares package revision `source_sha256` with existing immutable `content_revisions.raw_sha256` across edition→canonical work IDs, as well as detecting matching SHA shared by two distinct new package works. The decision is always **manual review required** for ambiguous work identity, not a merge or publication. Exact matching SHA proves source bytes match, but cannot prove the author's identity, edition equality, country/translation/audio rights or legitimacy of a separate canonical work. The read-only RR snapshot returns bounded candidate **work UUIDs** for a reviewer, without raw text. Hash duplicates across different titles are blocked at staging and rechecked during apply to prevent stale preview from silently creating new canonical works. Full authenticated reviewer resolution/dedup APIs and UI still belong to open #12/#19/#22/#23; no collision may be automatically approved.

## Taslak eser ilişkisini güvenli kaldırma (#12 kısmi)

Açık yetkili admin ilişki oluşturma API'sine iki küçük **DELETE** işlemi eklendi: `/v1/admin/catalog/works/:workId/titles/:titleId` ve `/v1/admin/catalog/works/:workId/authors/:authorId`. Bunlar yalnız **DRAFT esere bağlı ilişki satırını** siler, asıl kanonik `authors` kaydını, baskı/çeviri ilişkilerini, hak belgelerini, içerik revizyonlarını veya kaynak dosyalarını silmez. **Özgün başlık** (`kind=original`) hiçbir zaman bu işlemle silinemez; her eserde en az bir `author` veya `co-author` bağlantısı kalır. Bir `editor` tek başına eser yazarı sayılamaz. Başka yazar mevcut olsa bile son gerçek yazarın kaldırılması 409 reddi alır.

Her DELETE yalnız `{expectedVersion}` JSON kabul eder; mevcut bağımsız WRITE+READ opt-in, gerçek uygulama HTTPS, aktif account/session, bu cihazda MFA, PostgreSQL `catalog:edit` ve Web için HMAC-CSRF yeniden istenir. MFA/rol kilitleri, canonical work `FOR UPDATE`, ilişki denetimi, satır silme, metadataVersion +1 ve `work.title.remove`/`work.author.remove` önce-sonra audit aynı transaction içindedir. Veritabanı değişikliği ile audit birbirinden ayrı başarılı olamaz. İkinci işlem 409 stale veya 404 missing döner; varsayımsal/retry başarı yok. `requestId` ve aktör sunucu kaynaklıdır. Güncel özgün kimlik korunurken hatalı ilişki kaldırılabilir, referanslanan yazar yalnız başına silinmez.

Gerçek Folio-only `folio_test` PostgreSQL ve geçici HTTPS deneyi `admin-catalog-https-smoke` içinde kayıp HMAC-CSRF, read-only rol, cross-origin, yayımlanmış/eski sürüm payload, özgün başlık, son gerçek yazar, çifte silme, yarışan iki editör ve başarılı audit kanıtlarını kontrol eder. Tarayıcı E2E geçici TLS + açık mock API ile yanlışlıkla tek tıkta silmeme, kullanıcı onayından sonra 409, yalnız explicit reload, doğru sürümle kaldırma, özgün başlık/yazarın korunması, TR ve 390px erişimi test eder. Native cihaz ve gerçek tarayıcı+PostgreSQL tek test akışı ile kapsamlı dedup insan incelemesi henüz tamamlanmadığından #12 **AÇIK**.
