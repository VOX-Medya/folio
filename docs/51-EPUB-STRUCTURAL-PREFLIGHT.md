# Folio #26/#20/#46: bounded EPUB ZIP structural preflight (not publication)

## Scope and guarantees

The V1 quarantine `application/epub+zip` MIME admission initially checked only the first uncompressed OCF `mimetype` ZIP local header. That is **not proof of a complete valid EPUB**. This module adds `inspectEpubZipStructure(buffer)`, `LocalStorageAdapter.inspectEpubStructure(trustedQuarantineRow)` and `observePrivateQuarantineEpubStructure(db,storage,trustedOwnerId,trustedAssetId)`. They are **internal only**: no public API route, no media download, no input text extraction, no UI rendering, no file publication, no `verified` transition and no rights grant.

The implementation accepts a deliberately conservative **subset** of EPUB OCF ZIP archives, capped at **16 MiB on-disk, 512 members, 8 MiB per decompressed member, 32 MiB cumulative decompressed bytes**, with an additional **100:1 individual expansion ratio** guard. Only ZIP store and deflate compression and basic UTF-8/ASCII path names are handled. Supported general-purpose ZIP flags are UTF-8 names and (for members other than the first `mimetype`) optional data descriptors; both descriptor signature variants and all CRC/size bytes are checked. ZIP64, splits, overlapping/prefixed/appended bytes, archive comments, unknown flags, encrypted ZIP entries, ZIP member comments, unsafe modes/symlinks and nested archive extensions are rejected, not silently accepted.

The structural stage checks:

- The first, exact uncompressed EPUB OCF `mimetype` header and payload, followed by a **real** end-of-central-directory record with correct entry count, offsets and size.
- Every central member and matching local file header (names, methods, flags, data lengths, CRC-32). Full contiguous local member layout and a central directory with no unindexed bytes.
- Every stored/deflated member is expanded **in memory with Node zlib `maxOutputLength`**, compared against stated decompressed length and CRC-32; no ZIP files are extracted onto disk.
- Duplicate/case-folded names, traversal (`..` and `.` segments), absolute/Windows paths, backslashes, NUL/control bytes, percent-encoded ambiguous names, Unicode normalization ambiguities and ZIP Unicode-name override extras are refused.
- `META-INF/encryption.xml`, `META-INF/rights.xml`, embedded ZIP/EPUB/7z/rar/tar/gz archives and symlink entries are refused. `META-INF/container.xml`, at least one `.opf` package and one `.xhtml` resource must exist. **Presence alone is not XML parsing or proof of valid EPUB package/spine semantics.**
- A **trusted persisted `media_assets` row** fixes the private owner, UUID storage key, MIME, digest, size and `pending_verify` state. The inspector opens the private 0600 single-link inode via `O_NOFOLLOW`; it verifies actual SHA-256 and size and ensures inode/mtime/ctime are unchanged. Owner spoofing, modified bytes, symlinks and unsafe permissions fail.
- The DB observation runs the bounded file inspect outside a long-running transaction, then acquires the same advisory owner lock used by private quota/AV/GC, and rechecks metadata/status. Concurrent withdrawal/rejection invalidates the result. A successful transaction records only `structure_only`, entry/expanded counts, SHA and **`pending_verify`**, not paths, entry names, source text or full metadata.

**This is NOT EPUB safety, readability or licensing verification.** Not implemented: trustworthy `container.xml` rootfile resolution, `content.opf` XML parsing, manifest MIME references, spine/chapter order, XHTML/HTML sanitization, scripts/remote resource protection, mixed bidirectional text, reading provenance, decompression in a hardened subprocess, coverage of all valid EPUB ZIP options, legal territory rights, live scanner signatures, audio/PDF, or approved publication. A malicious or malformed XML document can pass **ZIP structure**; a correctly licensed but unusual ZIP may be refused by these intentionally strict checks. Keep it in `pending_verify` and present a controlled `Dosya yapısı desteklenmiyor` QA error in a future user-facing import workflow. Do **not** auto-correct or generate missing text.

## Tests and evidence

`packages/db/src/epub-structure.spec.ts` uses a custom local synthetic ZIP writer, not an imported copyrighted EPUB: valid EPUB OCF + deflate and streamed ZIP descriptor, wrong first header, missing container/package/XHTML, directory traversal and encoded paths, duplicates, ZIP symlinks, encryption/rights metadata, altered CRC/central/local offsets, truncated files, appended bytes, ZIP64 marker, malformed extra fields, nested archives, compression ratio bomb, international name flag, owner spoof, SHA mutation and chmod. All parsing remains structure-only even for unreadable XHTML bytes.

`bash infra/lab.sh storage-epub-smoke` runs only against Folio's loopback `folio_test` PostgreSQL database and disposable temporary vault. Its real two-pool integration checks valid owned preflight audit, absent/other owner denial, bare MIME header previously accepted by quarantine but **rejected by full ZIP parser**, an invalid/truncated EPUB never generating a success audit, a concurrent trusted rejection of a file while inspecting it, and no `verified` status or source/path/key leak. Normal `pnpm check`, isolated PG/HTTPS CI, Expo web/Android/iOS JavaScript exports, Chrome E2E, non-deploy Docker and synthetic ClamAV process smoke must all pass before merge.

Documentation upstream: [W3C EPUB OCF](https://www.w3.org/TR/epub-34/#sec-ocf) and [ZIP APPNOTE](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT). Deployment still **BLOCKED** by #7 dependency advisories and #26's unfinished full semantic/media/right and actual-device acceptance. No deployment or production build has been authorized.
