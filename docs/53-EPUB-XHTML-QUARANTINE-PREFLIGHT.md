# Folio #20/#26: XHTML syntax and local-reference quarantine preflight (not rendering)

## Boundary

The previous [ZIP-CRC gate](./51-EPUB-STRUCTURAL-PREFLIGHT.md) and [OPF package/spine gate](./52-EPUB-PACKAGE-SPINE-PREFLIGHT.md) respectively prove only bounded OCF ZIP structure and conservative local OPF manifest/spine relationships. This stage adds **separate** `inspectEpubZipXhtmlMarkup`, `LocalStorageAdapter.inspectEpubXhtmlMarkup` and `observePrivateQuarantineEpubXhtmlMarkup`, available only inside the backend to a trusted owner for a persisted private `pending_verify` EPUB.

A positive observation is **`xhtml_markup_only`**, **not** EPUB validation, an HTML sanitization result, render approval, rights proof, full text extraction, publication or a `verified` transition. Source ZIP, XHTML text and chapter path bytes are never returned to callers or included in audit. No HTTP media endpoint, file stream, CSS injection, browser UI component, AI correction, OCR, generation or external fetch was added.

## Conservative supported syntax

- Input: ZIP file capped at 16 MiB, 512 entries, 8 MiB decompressed per member, 32 MiB total expanded, 100:1 ratio. ZIP member names and sizes, stored/deflated CRC are checked *first*. A *single* rootfile, valid OPF manifest, exact local nav XHTML and linear spine relationship must pass *second*. All XHTML manifest resources, not merely linear chapters, are checked in this third stage.
- Each XHTML is decoded as **fatal UTF-8**, max **2 MiB** each, max **128** XHTML documents, **8,000** elements per document, **50,000** elements and **4,096** links across the entire EPUB, max depth **64** and max tag length **4 KiB**. Malformed XML, unbalanced tags, duplicate IDs, duplicate attributes, invalid controls, ambiguous namespace and noncanonical code points are refused.
- Only the XHTML namespace `http://www.w3.org/1999/xhtml` with `html/head/title/body` document structure and an intentionally small inert, textual element allowlist is accepted. Root-only optional `xmlns:epub` is fixed to `http://www.idpf.org/2007/ops`, and the one `nav epub:type="toc"` document must contain at least one local link under an HTML list item. The ordinary chapters cannot forge a TOC.
- Accepted metadata attributes are restricted to `id`, `lang`, `xml:lang`, `dir`, `class`, `title` plus `href` **only** on `a`, and `epub:type="toc"` only on navigation; duplicate/mismatched language attributes are rejected. **No** event handlers, `style`, `xml:base`, DOM scripting attributes, `src/srcset`, alternate protocols, namespace overrides, embedded objects, custom tags or unlisted attributes.
- All `a href` values must be same-package, exact-case, unencoded, local `.xhtml` paths or `#fragment` references. No `https://`, `file://`, `javascript:`, `data:`, protocol-relative links, query strings, percent escapes, parent traversal, missing resources or unresolved fragment IDs. Cross-document fragment checks happen only after **all** XHTML files are parsed; nothing loads from the network.
- Strict XML subset: built-in five named XML entities only; no `DOCTYPE`/external entities/recursive entities/HTML named entities/numeric entities, CDATA, comments, processing instructions other than an initial strict XML 1.0 UTF-8 declaration, or ambiguous root/multiple bodies. Unsafe features **fail closed**, and no source is repaired.

These deliberately restrictive rules may reject legitimate EPUBs with MathML, illustrations, richer EPUB 3 XHTML, complex accessibility metadata, internal upward-relative links, footnote navigation, embedded images or scripted interactive media. This is an *internal conservative preflight*, not a statement of full EPUB compliance. Unsupported files must not be silently modified.

## Essential unimplemented gates

**Still unverified and unusable for release:** OPF Dublin Core/source provenance, semantic paragraph and reading order, document/sentence/page/footnote classifications, bidirectional script and RTL inspection, EPUB/XHTML validator in a hardened subprocess, **all CSS contents/imports/remote URL and fonts**, image/media decoding and embedded asset safety, AV official current signatures and process isolation, PDF real text flow/column semantics, source licensing/territory publication rights, owner-RBAC authorized streaming/Range/TTL, persistence of ordered revisions/reader references, offline sync, real iOS and Android device QA, and user-facing localized error states. A *malicious CSS file can pass this XHTML-only gate by design*, because CSS is not opened or rendered by it. This is covered by an explicit negative-capability test.

## Audit and reproducibility

`readTrustedEpubBytes` verifies the private 0600 single-link local file opened with `O_NOFOLLOW`, persisted owner UUID/key/MIME/pending state, actual SHA-256 and byte length, and inode metadata/identity before and after. DB observation accepts only trusted principal + asset UUID, reconstructs all expected bytes fields from the private PostgreSQL `media_assets` row, runs the bounded checks outside the transaction, then takes the per-owner advisory transaction lock to recheck the unchanged media row and `pending_verify`. In-flight withdraw/rejection produces **no success audit**.

The event `storage.quarantine.epub_xhtml_observed` stores **only** `xhtml_markup_only`, document/element/TOC/local-link/fragment counts, SHA digest and unchanged `pending_verify` state. No document paths, original title/author, XHTML source or private blob key are persisted.

Unit corpus: `packages/db/src/epub-structure.spec.ts` includes independent synthetic OCF, negative cases for script/iframe/image/svg/math/style/on-event/XML namespaces, untrusted external/data/javascript links and encoded traversal, forged/duplicate IDs and invalid local TOC fragments, DTD/XXE/custom/numeric entities, malformed UTF-8/markup, size/nesting bombs and constrained access. The full existing `bash infra/lab.sh storage-epub-smoke` runs **only** against Folio isolated loopback `folio_test`, with two database pools, owner denial, positive counts-only observation, source non-disclosure, no `verified`, and mid-inspection concurrent rejection. GitHub Ubuntu CI also runs contracts/backend/app tests, Expo Web/Android/iOS **JavaScript exports only**, Chrome Playwright E2E, local no-deploy Docker build and **synthetic-signature-only** ClamAV native protocol test.

Release remains blocked by #7 unresolved dependency vulnerabilities (as of last audit: 2 high, 3 moderate) and #20/#26/#46 remaining real media/sanitization/rights/native-device acceptance. **No production build, deployment or book publication is authorized.**
